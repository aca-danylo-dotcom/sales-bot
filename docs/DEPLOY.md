# Деплой на Railway

Бот и веб-панель — один процесс, поэтому сервис на хостинге тоже один. База
SQLite и фотографии товаров лежат на **постоянном диске** (Volume): папка с
кодом на хостинге создаётся заново при каждом обновлении, и всё, что записано
рядом с кодом, при следующем деплое исчезнет вместе с заказами.

Всё, что описано ниже, делается один раз. Дальше обновление — это `git push`.

---

## 0. Перед началом

- Репозиторий: `git@github.com:aca-danylo-dotcom/sales-bot.git`, ветка `main`.
  Railway берёт код оттуда, локальная папка ему не нужна.
- Под рукой понадобятся значения из вашего `.env`: токен бота, `ADMIN_ID`,
  ключ kie.ai, реквизиты карты, адрес Google-таблицы.
- Тариф: на Railway хватает Hobby (~$5 в месяц). На пробном периоде поднимется
  и без оплаты, но бот там засыпает вместе с исчерпанием кредитов.

---

## 1. Создать сервис из репозитория

1. [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub repo**.
2. Выбрать `aca-danylo-dotcom/sales-bot`, ветку `main`.
3. Railway увидит `Dockerfile` и `railway.json` и соберёт образ сам.
   Первая сборка **упадёт или уйдёт в перезапуск** — это нормально: переменных
   ещё нет, бот честно говорит «Не задана переменная BOT_TOKEN». Настраиваем
   дальше, потом перезапустим.

Панель написана на React и собирается **внутри** образа, первой ступенью
`Dockerfile` (Node ставится только там). Готовые файлы уезжают в `web/dist`, а
отдаёт их всё тот же Python — процесс на хостинге по-прежнему один. Складывать
`web/dist` в репозиторий не нужно: он в `.gitignore`.

Локально панель поднимается двумя способами:

```bash
cd web/frontend
npm install
npm run build   # разово: собрать в web/dist, дальше бот отдаёт её сам
npm run dev     # или dev-сервер на 5173 с горячей перезагрузкой
```

`npm run dev` ходит за данными на `localhost:8080` — то есть бот должен быть
запущен рядом. Если открыть панель без сборки и без dev-сервера, вместо неё
будет понятное сообщение «Панель не собрана».

---

## 2. Подключить постоянный диск

1. В сервисе → **Variables/Settings → Volumes** → **New Volume**.
2. **Mount path**: `/data`.
3. Размер по умолчанию (1 ГБ) — с запасом: база магазина весит килобайты,
   основное место занимают фотографии товаров.

Диск переживает деплои и перезапуски. Именно на нём будут жить `shop.db`
и папка `media` с фото.

---

## 3. Задать переменные

Сервис → **Variables** → **Raw Editor**, вставить и заполнить своими значениями:

```
BOT_TOKEN=токен_от_BotFather
ADMIN_ID=ваш_телеграм_id

AI_API_KEY=ключ_kie
AI_BASE_URL=https://api.kie.ai/codex/v1
AI_MODEL=gpt-5-5
AI_REASONING_EFFORT=low

SHOP_NAME=Sport Store
SHOP_CITY=Киев
SHOP_CURRENCY=грн
DELIVERY_INFO=Новой Почтой по всей Украине, отправка на следующий рабочий день после оплаты.
PAYMENT_INFO=Предоплата на карту — реквизиты бот присылает при оформлении заказа.
RETURN_INFO=Обмен и возврат в течение 14 дней, если товар не был в использовании.

PAYMENT_CARD=номер_карты
PAYMENT_CARD_HOLDER=IVAN PETRENKO
ORDER_PAYMENT_TIMEOUT_HOURS=24
CART_REMINDER_HOURS=6

PROMO_PERCENT=5
PROMO_TTL_DAYS=3
WINBACK_ENABLED=1
WINBACK_AFTER_DAYS=14
WINBACK_COOLDOWN_DAYS=30
WINBACK_BATCH=20

SMTP_HOST=
SMTP_PORT=587
SMTP_USER=
SMTP_PASSWORD=
SMTP_FROM=
SMTP_FROM_NAME=

TIMEZONE=Europe/Kiev

DB_PATH=/data/shop.db

SHEETS_WEBHOOK_URL=
SHEETS_WEBHOOK_TOKEN=
```

Что здесь важно:

- **`DB_PATH=/data/shop.db`** — главная строка всей настройки. Без неё база
  ляжет рядом с кодом и пропадёт при первом же обновлении бота. Папку `media`
  бот заведёт сам рядом с базой, отдельно указывать не нужно.
- **`PORT` и `WEB_HOST` не задавать.** Порт Railway сообщает сам, а панель
  должна слушать все интерфейсы, иначе хостинг до неё не достучится.
- **`PROMO_PERCENT` и `WINBACK_ENABLED` — это деньги и сообщения клиентам.**
  Значения выше включают скидку 5% в напоминаниях и рассылку «давно не
  заходили». Если такого пока не нужно, ставьте `PROMO_PERCENT=0` и
  `WINBACK_ENABLED=0` — бот продолжит напоминать о брошенной корзине, но без
  скидки, а «уснувшим» писать не будет вовсе. Переменные заданы явно нарочно:
  без них подставятся те же 5% и включённая рассылка, только молча.
- **`SMTP_*` пустые — письма выключены**, напоминания идут только в Telegram.
  Заполнять есть смысл, когда у клиентов начнут появляться адреса (почту они
  оставляют сами — шаг «Пропустить» при оформлении или команда `/email`). Для
  Gmail в `SMTP_PASSWORD` нужен **пароль приложения**, а не пароль от аккаунта.
- `SHEETS_*` — из `docs/GOOGLE_SHEETS.md`. Можно оставить пустыми: бот работает
  и без выгрузки в таблицу.
- `AGENT_STATS_URL` / `AGENT_STATS_KEY` не задаём — телеметрия магазина пока
  выключена сознательно.

---

## 4. Дать панели адрес

Сервис → **Settings → Networking** → **Generate Domain**.

Railway выдаст адрес вида `sales-bot-production.up.railway.app`. По нему
откроется веб-CRM. Проверка живости настроена на `/health` — эта страница
в базу не ходит и заодно показывает, куда база легла (см. шаг 6).

Панель работает без входа: кто знает адрес, тот внутри. Адрес — рабочий,
раздавать его посторонним не нужно.

---

## 5. Остановить бота на своём компьютере

Telegram отдаёт сообщения **только одному** получателю. Если локальный
`python bot.py` продолжит работать, два экземпляра начнут отбирать друг у друга
обновления: в логах пойдёт `TelegramConflictError`, а клиенту ответит то один
бот, то другой — с разными базами.

Поэтому перед первым запуском на хостинге локального бота закрываем.

---

## 6. Запустить и проверить

Сервис → **Deployments** → **Redeploy**. Дальше по логам:

```
Бот запускается...
База данных готова: /data/shop.db          ← путь на диске, не /app
Планировщик запущен: ...
Веб-CRM слушает http://0.0.0.0:XXXX (без входа)
Run polling for bot @store_assistant1_bot
```

Что проверить руками:

0. Открыть `адрес-сервиса/health`. Ответ должен быть таким:

   ```json
   {"status": "ok", "storage": "volume", "db": "/data/shop.db", "media": "/data/media"}
   ```

   `"storage": "volume"` — база на постоянном диске, всё в порядке.
   `"storage": "ephemeral"` — диск не подключён или не задан `DB_PATH`: товары
   и заказы переживут перезапуск, но исчезнут при следующем обновлении кода.
1. Открыть выданный адрес — должна открыться сводка панели.
2. Завести в панели тестовый товар с фото, обновить страницу — фото на месте.
3. Написать боту в Telegram `/start` — он отвечает.
4. Сервис → **Redeploy** ещё раз. После перезапуска товар и фото **остались** —
   значит диск подключён правильно. Если пропали, `DB_PATH` не задан или Volume
   смонтирован не в `/data`.

---

## 7. Дальше: обновления и данные

- **Обновление кода** — `git push` в `main`: Railway пересобирает образ и
  перезапускает сервис сам. База и фото при этом не трогаются.
- **Остановка** — сервис → **Settings → Remove/Pause**. Бот перестаёт отвечать,
  диск с данными остаётся.
- **Резервная копия.** Заказы и остатки бот раз в 10 минут выгружает в
  Google-таблицу — это и есть копия на каждый день. Сам файл базы лежит на
  диске Railway; чтобы скачать его, нужен их CLI (`railway ssh`), это отдельная
  процедура и в обычной работе не требуется.
- **Перенос существующей базы** (если когда-нибудь понадобится залить на новый
  пустой диск базу с компьютера): переменная `DB_SEED_GZ_B64` — файл `shop.db`,
  сжатый gzip и закодированный base64. Бот развернёт её **только если** по
  `DB_PATH` файла ещё нет; после первого запуска переменную можно удалить.
  Фотографии так не переезжают — их заливают через панель.

---

## Если что-то пошло не так

| Что видно | В чём дело |
|---|---|
| `Не задана переменная BOT_TOKEN` | Переменные не сохранились или сервис не перезапущен после их добавления. |
| `TelegramConflictError` | Где-то работает второй экземпляр бота — обычно локальный на компьютере. |
| Товары и фото пропали после деплоя | Не задан `DB_PATH=/data/shop.db` либо Volume смонтирован не в `/data`. |
| Healthcheck не проходит, деплой откатывается | Бот не дошёл до запуска панели — смотреть строку с ошибкой выше в логах. |
| `Google Sheets: скрипт ответил HTTP 404` | Развёртывание Apps Script устарело, нужен новый адрес `/exec` (см. `docs/GOOGLE_SHEETS.md`). |
